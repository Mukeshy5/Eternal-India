The Staff Panel is available at `/staff/login`. In the Technical Panel, open **Staff Login Accounts** (`/technical/staff-accounts`). Verify an Employee ID from Staff Management, enter or generate credentials, and create the account. Staff have no registration endpoint.

Only the `/api/technical` namespace and an authenticated technical role can create, activate, deactivate, reset or delete login accounts. Employee status is also checked on every staff request. Account changes revoke all staff sessions; employee deactivation revokes existing sessions even if the employee is later reactivated. Deleting a login retains employee, attendance, enquiry, invoice and voucher records.

Staff authentication uses the existing bcrypt password helper, a separate JWT audience, a separate HttpOnly cookie, MongoDB session records and a revocation version. Use the existing `AUTH_TOKEN_SECRET` configuration (or its existing session-secret fallback). No new environment variables or database credentials are needed. Production requires HTTPS, as with the existing panels.

All active Staff Logins can view the shared, unarchived enquiry inbox and customer details. Every new Website, WhatsApp or Gmail enquiry creates one durable notification per active linked employee, including unassigned enquiries. Assignment still controls status edits: staff may update only their currently assigned enquiries using the current revision. They cannot assign, archive or delete enquiries.

Journey vouchers use the existing voucher editor, pricing, numbering, PDF and export implementation. Records created in Admin, Technical or Staff appear in every panel's register, detail view, totals, filters and exports. Staff can edit/delete their own vouchers; other creators' vouchers are read-only with print/download available. A staff owner is stored as `staff:<employee MongoDB ID>` in `createdBy`, keeping ownership stable when a login is recreated. Shared hotel, office and GST configuration remains available for voucher creation.

**Billing / Invoice** uses the same shared register in all panels, with existing numbering, validation and PDF generation. All active staff can view/download any saved invoice, and create new invoices. Staff can edit/delete invoices created by their own login; other invoices remain read-only. **Manage access → Invoice update alerts** controls optional notifications for selected invoices using the existing `authorizedStaffIds` field; subscribing/unsubscribing does not hide a shared invoice. Personal attendance, ID cards and notification read/dismiss state remain scoped to their employee.

Activity History includes shared enquiry, journey, invoice, hotel, GST and office-address changes from every panel. Staff also see their own account activity; Technical can separately enable other staff-account activity. Admin and Technical administrators can permanently delete individual activity records or all records matching the current search/category filters. Staff can permanently delete only their own activity; shared and other employees' records remain protected. Deletions remove MongoDB documents and are not logged back into the history being cleared.

Admin, Technical and Staff use authenticated Socket.IO for shared workspace changes; Staff also use the credentialed `/api/staff/events` SSE stream for private notifications. Successful business writes immediately notify both transports, including when only Staff clients are connected. Staff translate workspace events into register, detail, configuration and activity-history refreshes without remounting editors. SSE also checks authentication and database revisions every three seconds, recovering cross-instance changes and fresh durable notifications. Reconnect, focus and periodic refresh recover interruptions. Notification IDs suppress duplicate popups/audio; the existing notification ring is enabled with a browser gesture. Staff never join the privileged Admin/Technical socket rooms.

New collections: `staff_accounts`, `staff_tokens`, `staff_notifications`, `staff_account_audit`. Unique indexes enforce one login per employee and username. Startup creates these collections/indexes without migrating or deleting existing business records.

Run `node --test --test-concurrency=1 test/app.test.js test/staff-portal.test.js` from `Backend` to cover permanent deletion, filtering and Staff ownership. `npm --prefix frontend run verify:staff-panel` tests the React UI with a separate database and injected incoming stream events; `npm --prefix frontend run verify:responsive` checks desktop, tablet and mobile breakpoints. Run `npm run build` for production validation. Deploy both the updated Render backend and Vercel frontend for the live panels to use this behavior; no new environment variables are needed.
